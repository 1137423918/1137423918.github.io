并发清理产物时，
让已消失的文件正常退出。

两个 Agent 服务实例共享产物目录时，清理操作可能重叠。Google ADK 的文件产物服务先检查版本目录存在，再递归删除；另一方若在这期间删掉目录、内容或元数据，当前调用会抛出 FileNotFoundError。

使用真实 FileArtifactService 与真实文件系统复现，固定上游 commit c81876a4。没有 GPU、模型或云 API 调用；这是一项 SDK 文件存储修复，不是新增 Agent 运行时适配器或模型能力评测。

从可控调度到自然并发

回归用屏障控制两个服务都通过存在性检查，再让其中一个先完成删除。另一项检查让已经枚举的内容在 unlink 前被真实删除。原版在三项检查中失败，真实权限错误对照通过。

每轮创建同一父产物的三个版本与一个嵌套产物，再从两个独立服务实例同时调用删除。自然并发没有强制调度顺序；20 轮观察不能当作通用可靠性指标，也没有据此声称性能提升。

只忽略已经消失的项

修复使用 rmtree 的异常回调，仅接受 FileNotFoundError；权限等其他异常继续报告。Python 3.11 适配 onerror 的异常元组，3.12 及之后使用 onexc。目录遍历中消失的内容也会被处理，避免只修复存在性检查之后的一个窗口。

现有嵌套产物布局与清理空父目录的逻辑保留。真实权限检查确认所选不可写版本目录会报告 PermissionError，恢复权限后内容仍可读取；递归删除并非事务，这不代表所有 I/O 失败都能回滚。
