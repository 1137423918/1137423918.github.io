DURABLE WORKFLOWS / SQLITE / 2026.11.21

工作流恢复了，
数值不该悄悄变成空值。

Agent 工作流中的工具结果可能包含非有限数值。LFX 的检查点本应保真保存结果，或明确放弃缓存、在恢复时重新计算。但在固定版本中，NaN 和正负 Infinity 可以变成 JSON null，生产节点仍被标为已完成，下游却读到了 None。

服务器 CPU 上复现并修复。检查点与持久化服务套件 105 项通过，包含真实 SQLite 重开和连接图恢复。补丁和完整证据已公开；GitHub 拒绝导入上游发布分支，等待 workflow 权限授权，候选尚未推送、PR 尚未创建；广泛图套件仍有失败，结果单独披露。

从可写入，到可正确恢复

同一个公开驱动将 NaN、正 Infinity、负 Infinity 分别放入标量、嵌套容器和 LFX Data，保存到真实 SqliteCheckpointStore，再通过新 store 加载。原版的九个非有限案例均变成 None，且没有 opaque-drop 标记；三个有限值对照正常。

原版：非有限值 → 标为可恢复 → JSON null → 生产节点仍 built
修复：非有限值 → 显式 opaque drop → 恢复时按现有机制重算

LFX Data 的 model_dump(mode="json") 就可能先丢失非有限值。因此候选在导出前检查原始模型字段，也拒绝标量非有限值，并检查导出后序列化器新引入的非法 JSON 数值。它复用已有的丢弃与重算协议，没有新增 wire 类型或改动通用 API 输出清理。

验证真实的生产与消费关系

回归通过 .set() 连接数字生产组件与消费组件，先执行生产节点，再保存、重开 SQLite、恢复 Graph。非有限案例必须取消生产节点的 built 状态，重新产生数值，并完成下游比较；有限值节点保持 built。组件配置使用数字字符串，保证工作流定义本身可以正常保存。

工程边界与上游状态

固定 Langflow release-1.14.0 基线 4d3b965c，贡献指南要求投向活跃发布分支。投稿前已复核仓库未归档、允许 PR，并检查现有工作避免重复。当前 GitHub 发布权限状态独立记录，没有把本地提交写成上游 PR。一般输出将 NaN 清理为 null，与检查点决定缓存能否信任，是不同的处理环节。

无法找回旧检查点已经丢失的数值；工作流定义本身必须可保存为 JSON。重算可能重复生产节点的副作用，没有 exactly-once 保证。这里只验证编码器支持的原生浮点、容器与模型路径，不保证任意自定义序列化器或全部数值库。实验使用受控组件，无模型推理或 GPU，不计为模型自主修复成绩。
