MODEL EXPERIMENT / 2026.11.20

没有空闲 GPU 时，
先让失败留下证据。

我在授权 Linux 服务器的 CPU 上运行了固定版本 Qwen3-4B-Instruct-2507，把真实神经模型接入已有维护运行器。FP32 与动态 INT8 各完成正常、检查点恢复两种尝试，四次都没有生成补丁，也没有进入官方验收。

这是一个公开 Deep Agents 路径问题的两种精度、两种运行方式。它不能换算为通用任务成功率；此前脚本驱动的恢复与修复通过结果仍单独记录。

先固定任务，再保留失败

任务固定到 Deep Agents 744a797e，只允许改动两个文件。模型收到问题现象，没有收到参考补丁或编辑计划。操作者验收仍为官方测试加 28 个不可编辑契约，没有为模型输出放宽标准。

四次请求均有 2,262 个输入 token，触及 170 秒生成时限。每请求最多 1,536 个输出 token、180 秒请求上限，每场景 600 秒、40 个图步骤，贪心解码与 seed 42 不变。两次恢复中断时工具结果为零，未覆盖“已完成工具操作后继续”的模型恢复能力。

格式兼容也是实验变量

INT8 的维护输出出现了未提供函数的 schema 文本。随后单独声明并运行一个短诊断，只要求调用已提供的 read_file。模型在 11.866 秒生成 20 个 token，原始文本为：

({"name": "read_file", "arguments": {"file_path": "/sample.py"}})

输出没有原生 <tool_call> 标签，当前严格解析器返回普通文本，未执行工具。短诊断只说明观察到了格式互操作缺口，不能算作维护成功。时间截断与格式偏离同时存在，尚不能归结为单一根因或模型本身的能力上限。

资源与可复现边界

CPU 为 Xeon E5-2699 v4，Torch 2.8.0、Transformers 4.57.1；使用 4 个计算线程、nice 19、48 GiB 地址空间与 36 GiB RSS 上限。服务只监听本机回环地址。INT8 对除输出头外的 252 个 Linear 层做动态量化，其他部分仍为 FP32，原始权重不改写。

模型 revision 为 cdbee75f17c01a7cc42f958dc650907174af0554；12 个文件共 8,060,915,998 字节，按固定官方元数据重新校验。两份服务源码、独立协议、七次真实生成响应、日志与哈希均公开。完整维护请求、检查点数据库和工作区不公开。

本轮模型服务均已核对进程身份后关闭。短文本 smoke 只用于验证传输；没有用单次延迟声称通用加速比，也没有把 INT8 的 token 增多解释为质量提升。该服务是实验接口，不是生产推理平台。

可以继续解决的问题
