撤销失败之后，
为什么跳过了上一版？

代码维护 Agent 依赖文件工具完成编辑，也依赖撤销来恢复错误操作。OpenHands SDK 的撤销路径在写回文件之前就移除了历史；当写回失败时，文件没有改变，但下一次重试已经失去了应恢复的版本。

上游 草稿 PR #7032 已提交，尚未合并。真实权限复现与 185 条相关回归均在服务器完成，无模型或 GPU 调用。上游 HUMAN 说明等待本人填写，保持 Draft。

沿着公共工具复现

固定 OpenHands SDK 基线 722e5d4，在 Linux、Python 3.13.18 下使用冻结依赖。以普通用户调用公共 FileEditorExecutor 与 FileEditorAction，连续两次正常编辑，令文件内容依次为 0、1、2。随后把目录改为只读，阻止撤销的原子替换；恢复目录权限，再撤销两次。

只在写回成功后消费历史

改动保留既有同文件操作串行化机制，增加不消耗记录的历史读取，再在写回成功之后弹出记录。成功撤销仍遵循后进先出；写回失败保留同一个待撤销版本。

原版：pop history → write restored file
修复：peek history → write restored file → pop history

永久回归通过公共 FileEditorTool 调用，在 Path.replace 注入 PermissionError，兼容具有 root 权限的 CI；真实目录权限复现单独保留，避免只从模拟异常推断实际文件系统行为。
