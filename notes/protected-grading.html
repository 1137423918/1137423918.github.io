测试通过之前，
先保护验收本身。

真实维护任务允许 Agent 改生产文件，也需要它新增测试。但若只跑候选自己的测试，一份删弱测试的补丁也可能显示通过。我为维护运行器增加固定原版测试副本，并在导出前检查声明的 Python 文件语法。

本轮使用明确的脚本计划，在固定 Deep Agents 仓库上比较验收策略，并重放此前真实模型的无效写入。它验证运行器的行为；新模型任务尚未运行，旧模型失败结果保持原样。

同一份候选，两种验收

控制候选包含原先的路径修复，同时故意把另一个生产函数 regex_literal_hint 改成始终返回 None，并跳过对应测试组。路径契约仍然全部通过；真正被破坏的是另一项已有行为。

两种策略检查相同的 2,807 字节候选补丁，SHA-256 为 41d742b5…75c871b。原版测试与候选测试存在重叠，不能把两组通过数量相加为独立覆盖。

原版与新增测试都要保留

运行器从固定 commit 创建独立 worktree，把候选生产代码复制进去，测试文件使用基线原始字节。候选自己的测试继续在主 worktree 运行，因此合理新增的回归测试也保留。命令还核对原版测试哈希与实际导入来源。

验证结束、缓存复用和失败反馈之前，检查副本内容、HEAD、改动范围以及日志哈希。若验证命令改写了副本中受检查的已跟踪内容，即使退出码为 0 也会停止。视图准备中断后只接受原版或预期候选这两种已知文件状态。

这是受控运行器的完整性协议，不是恶意 Python 程序的系统级沙箱；它没有证明覆盖所有未跟踪文件、依赖与主机写入。新任务在旧 worker 上会于固定验收命令处拒绝继续，不能误记为成功。

用真实失败文本验证导出保护

上一轮模型留下的 900 字节虚拟文本含字面反斜杠 n，静态语法无效。本轮直接重放原文本，显式语法策略在创建候选 worktree 和补丁之前拒绝导出。没有自动解码或补写参考实现。

语法检查采用 worker 的 Python 3.11，不能替代其他 Python 版本、类型检查或业务测试，也不能阻止所有大范围覆盖。它解决的是已经观察到的无效 Python 导出问题。

检查与复现
